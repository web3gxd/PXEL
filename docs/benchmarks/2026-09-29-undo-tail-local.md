# Local guarded undo tail scan, 2026-09-29

This is one preliminary functional timing sample, not a percentile, SLA or CI threshold. The ignored real-PostgreSQL harness is `journal::tests::undo_tail_scan_timing`, invoked with `cargo test -p spreadsheet-storage undo_tail_scan_timing -- --ignored --nocapture`. It commits 1,000 unrelated durable events after the target write, then times one `UndoCell` commit. The measured span includes journal lookup/verification of the tail, document lock, CAS and PostgreSQL commit; it does not isolate the lock hold or fsync time. `synchronous_commit=on` is set by the commit transaction; the harness does not remeasure the host's `fsync` and `full_page_writes` settings.

Host: Windows 10.0.26100, Intel Core Ultra 9 185H, 22 logical CPUs, approximately 15.6 GiB RAM; PostgreSQL 18.6 on local loopback. Rust was run in test profile. The final implementation streams the verified tail one row at a time; one observed commit wall time was **22.461 ms**. Setup and 1,000 precursor commits were outside the timed span. A previous `fetch_all` prototype produced one 19.055 ms sample, which does not describe the final implementation. A release-profile repeated benchmark with lock hold instrumentation is required before any p95 or 50 ms target claim for undo.
