# ADR-040: проверка snapshot + tail после аварийной остановки PostgreSQL

Статус: принят для локального recovery среза фазы 5, 2026-09-29.

## Контекст

Test-only interruption publisher и жесткий перезапуск backend проверяли разные
границы, но не аварийную остановку PostgreSQL после подтвержденной записи.
Корректный snapshot без проверки хвоста не доказывает восстановление последней
подтвержденной версии.

## Решение

Отдельный `just crash-recovery-postgres` запускает свежий приватный кластер
PostgreSQL 18 и backend с dev-auth, публикует ACTIVE snapshot версии 3,
подтверждает изменение версии 4 и немедленно останавливает БД командой
`pg_ctl -m immediate`. После повторного запуска PostgreSQL и backend тест
сверяет версию, содержимое, domain hash с ACK и историческую версию 3.

Runtime recovery пишет структурированное событие с версией выбранного
snapshot, числом примененных событий и временем восстановления. Содержимое
ячейки, формула и реквизиты доступа в событие не входят. Тест требует именно
snapshot v3 и один event хвоста, исключая случайный проход через полный replay.

Кластер запускается с `synchronous_commit=on`, `fsync=on` и
`full_page_writes=on`; он расположен в отдельном каталоге `.local` и не
останавливает рабочую БД проекта. После теста процессы останавливаются,
временный каталог удаляется.

## Границы

`immediate` stop проверяет восстановление WAL после аварии процесса, а не
физическую потерю питания, повреждение носителя, репликацию, резервное
копирование или PITR. Поддержка Linux и S3/Garage проверяется отдельно.
