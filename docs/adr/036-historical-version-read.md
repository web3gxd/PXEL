# ADR-036: чтение подтверждённой исторической версии

Статус: принят для read-only среза фазы 5, 2026-09-29.

## Контекст

Журнал хранит все подтверждённые события, а ACTIVE snapshots ускоряют
восстановление. Текущее `recover_document` всегда возвращало head, поэтому
историю нельзя было прочитать как точное состояние версии V. Пользовательский
undo не меняет прошлые версии и остаётся отдельной компенсирующей операцией.

## Решение

`GET /api/documents/{id}/versions/{version}` принимает десятичную версию
`1..head`, аутентифицирует пользователя и проверяет текущий ACL. Storage
выбирает самый новый проверенный ACTIVE snapshot не позже V и применяет
непрерывный хвост журнала только до V. Если подходящего snapshot нет или он
повреждён, восстановление начинается с genesis. Нулевой и будущий номер
получают `version_not_committed`; чужой workspace получает 404 без раскрытия
существования документа. Историческое чтение не меняет head, журнал,
calculation cache или actor projection.

Сервер ограничивает число одновременных исторических чтений двумя и каждый
recovery вызов 30 секундами. Ответ использует ту же JSON projection, что и
текущий документ. Рассчитанные значения формул сюда не входят: это
cacheless историческое состояние исходных значений и нормализованных формул.

## Границы

API предназначен для чтения отдельной версии, а не для browsing истории или
массового экспорта. Пока нет пагинации больших projection, исторических
calculation contexts/results и пользовательского UI истории. ACL проверяется
во время чтения; для HTTP-ответа нет такой же send gate, как для WebSocket.
Перед production нужна отдельная проверка гонки отзыва прав с HTTP body send.

## Проверка

SQLx-тест с PostgreSQL/LocalFilesystemBlobStore проверяет точный hash версии,
snapshot eligibility, replay хвоста, fallback без объектов, запрет будущих
версий и текущий head. HTTP integration test проверяет v1/v2, ошибки
версий, изоляцию чужого workspace и неизменность head.
