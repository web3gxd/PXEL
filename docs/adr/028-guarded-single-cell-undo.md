# ADR-028: Guarded undo of one authored value cell

Date: 2026-09-29. Status: ACCEPTED FOR THE NARROW PHASE-4 UNDO SLICE. Broader undo semantics remain open.

## Context

The current log records the result of `SetCellValue` and `ClearCell`, but not the overwritten content. Reversing the global document version would discard other users' work. Comparing the current value with an old result is also unsafe: another writer may have written the same value, or the cell may have changed away and back. The first undo slice must preserve those histories and use the same candidate/CAS/durable-commit flow as ordinary commands.

## Decision

The client sends `UndoCell { target_operation_id }` with a **new** operation ID. The target must be a newly recorded, single-cell `SetCellValue` or `ClearCell` event authored by the authenticated actor in the same document. Only a previous blank or plain `CellValue` is restored in this slice. A previous formula may be recorded as a preimage, but undo of it returns typed `NotUndoable` until restoring a historical bound AST across structural changes has a tested contract. Legacy events, batches, formula writes, axis changes and system events are not undoable in this slice.

New single-cell value/clear events use persisted schema 11. They contain the stable address, normalized result, original command kind and a bounded preimage of the previous `CellContent` (explicit blank versus value versus formula). The domain candidate verifies that the preimage equals the current authored content before applying the result; replay therefore checks it as well. The preimage is immutable history, not part of the resulting workbook hash, and is omitted from the ordinary wire `OperationCommitted` payload. Existing schema 1–10 bytes, hashes and replay semantics remain unchanged. An additive wire command has its own DTO; it does not reuse the persisted event encoding.

The actor loads and verifies the target event by `(document_id, target_operation_id)` after authorization. It refreshes its projection, rejects a deleted stable address, checks ownership and eligibility, then prepares a compensation candidate that restores the recorded plain preimage. Schema 11 authored writes and schema 12 compensations are two persisted encodings of the same domain `CellWrite` variant; schema 12 additionally records `compensates_operation_id` and target version. It is a new user-authored operation and increments the document version; it never deletes or rewrites the target event. The WebSocket canonical patch uses the existing `SetCellValue` or `ClearCell` kind, so older v1 clients can apply the resulting state. The compensating relationship remains in the durable event and can be exposed by a future history API. Calculation dirties that cell and its dependents just as an ordinary value edit does. The client keeps undo intent separate from its confirmed projection and does not treat an optimistic inverse as confirmed.

The journal repeats the guard **inside the commit transaction**, after locking the document and checking ACL/access epochs and before CAS. It verifies the target's actor and schema and rejects any later authored write to that same stable address, including `SetCellValues`, `SetCellFormula`, `ClearCell`, another recorded value or a compensation. Equal values and write-away/write-back still conflict. Unrelated cell edits may have advanced the head; the actor rebuilds the candidate at that head and retries the entire transaction on CAS/serialization conflicts. A missing/deleted target, changed cell or already compensated target yields typed, nonretryable `UndoConflict`; an ineligible target yields `NotUndoable`. The ordinary operation-ID receipt check runs first, so retrying a committed undo returns its original receipt even after later edits. Current authorization is required for that receipt as for other commands.

For the first slice, the journal scans and decodes at most 10,000 immutable events after the target while holding the document row lock. A target more than 10,000 versions behind the current head rejects with typed `UndoWindowExceeded` before scanning; the boundary is inclusive. This preserves correctness without assuming an unscanned cell was untouched. The lock duration and scan cost must be measured. A transactionally maintained cell-write index may replace the scan only with replay/concurrency correctness tests and a benchmark. A bounded replay of legacy events cannot reliably recover the preimage: the preceding write may be outside the window, so blank and an older value are indistinguishable. Full genesis replay on every undo would grow with document history and complicate snapshot activation. Schema-11 preimages make new undo independent of that scan; the scan remains solely the foreign-write guard.

## Compatibility and limits

Schema 11 and 12 are new immutable persisted formats. Decoders reject unknown schema/oneof values atomically; the storage codec, journal schema allowlist, canonical event hash and golden fixtures advance together. The wire protocol adds a distinct undo command and typed rejections without changing existing field numbers or the canonical cell patch kinds. A command with the same operation ID and different target remains an idempotency conflict. Source event preimages are server-derived and never accepted from a client. Preimage size counts against the persisted-event cap; an oversized preimage rejects the original write before commit rather than silently dropping undo history.

This is one-step undo of a recent own value/clear write, not a general per-user undo stack or redo. It does not undo a value batch, formula, style, copy, structural change or another person's write. Formula preimages, cut/move, historical source binding and a cell-write index each require separate compatibility decisions. The append-only operation log remains available after future snapshots; snapshot compaction must not remove history still eligible for undo without a documented retention/window rule.

## Required verification

Domain and codec tests must cover blank/value preimages, no-op/equal-value writes, formula preimage refusal, candidate hash and schema-11/12 replay, and preservation of old golden events. PostgreSQL tests must cover own undo, another actor's target, a foreign same-value write, write-away/write-back, batch or formula write after the target, unrelated concurrent write, CAS retry, same-ID retry after ACK loss and different-target ID reuse. Recovery must restart between original commit and undo and between undo commit and ACK, then compare direct replay hashes. Two-browser tests at DPR 1/2 must prove a successful own undo is broadcast, persists after reload and never erases a later foreign edit. The tail-scan benchmark records document history size, lock hold time and the chosen window; no p95 claim is made before measurement.
