# ADR-050: ограниченный отчёт о потерях при scalar XLSX import

Status: accepted for the next phase-6 slice (2026-09-29).

## Проблема

До этого среза OOXML reader извлекал поддержанные scalar cells, но мог
пропустить стили, merges, параметры листа и дополнительные package parts.
Атомарность импорта не защищает от такой тихой потери данных.

## Решение

`NormalizedWorkbook` содержит упорядоченный список типизированных
`CompatibilityIssue` без имён листов, текстов ячеек и формул. Reader отмечает
дополнительные package parts, workbook metadata, worksheet metadata,
форматирование строк и ячеек. Повторные признаки одной категории на листе
сводятся к одной записи; максимум 128 записей. Отчёт пересекает границу
дочернего worker в новом version-3 frame. Parent повторно валидирует типы,
порядок, уникальность и индексы листов. Unknown code/version не применяется.

По умолчанию `xlsx-import` отказывает до создания документа, если отчёт не
пуст. Локальный оператор может передать `--allow-loss`: CLI всё равно выводит
коды предупреждений и затем публикует только поддержанные scalar cells.
Это явное согласие относится к одному запуску команды и не сохраняется в
документе. Без флага подготовка событий также отказывает; один CLI check не
является единственной границей. `export_scalar_xlsx` отвергает IR с issues,
чтобы не потерять report при библиотечном round-trip.

## Границы и дальнейшая работа

Отчёт пока агрегирован по категории и индексу листа, не перечисляет каждую
ячейку/атрибут. Некоторые OOXML конструкции reader уже отвергает до отчёта;
полной классификации профиля и job/audit record нет. Metadata из
`[Content_Types].xml`, root attributes и редкие extension points требуют
дополнительного анализа. Даже с `--allow-loss` это локальный dev import:
публичная загрузка остаётся закрытой до OS sandbox, malware scan, durable
import job и user-facing report. Старые persisted events не меняются;
version-2 worker frames намеренно отвергаются parent после обновления.
