# ADR-038: хранение двух последних ACTIVE snapshots

Статус: принят для локального среза фазы 5, 2026-09-29.

## Контекст

ADR-037 убирает незавершённые публикации, но старые ACTIVE snapshots
накапливаются бессрочно. Журнал операций остаётся полным и позволяет
восстановить любую подтверждённую версию без снимка. Удаление единственного
резервного снимка увеличивает время восстановления при повреждении нового.

## Решение

Раз в час worker выводит из `ACTIVE` в `REJECTED` не более 100 снимков,
которые старше `PXEL_SNAPSHOT_ACTIVE_RETENTION_DAYS` (по умолчанию 30 дней).
Снимок пригоден для вывода только при наличии как минимум двух ACTIVE
снимков **разных более новых document versions**. Preferred snapshot не
выводится. Выбор и переход выполняются одним SQL statement с
`FOR UPDATE SKIP LOCKED`; trigger сохраняет неизменность identity и payload
metadata. Следом ADR-037 удаляет объект по retained `REJECTED` metadata и
периодически повторяет delete. Journal и его versions не меняются.

`ACTIVE` означает, что publisher прочитал и проверил объект при активации.
GC не сканирует все новые объекты повторно: по умолчанию сохраняются два
последних поколения, а при их потере reader откатывается к полному журналу.
Историческое чтение после удаления старого snapshot корректно, но может
стать медленнее. Защита от полной потери диска требует внешнего backup/PITR.

## Проверка и границы

PostgreSQL/LocalFilesystemBlobStore test создаёт четыре committed версии и
четыре ACTIVE снимка. Он проверяет age cutoff, batch size 1, сохранение двух
новейших, preferred pointer, удаление старых объектов, чтение версии 1 полным
replay и восстановление head через v3 после потери объекта v4. Параллельные
GC workers, S3 consistency, power-loss и PITR этим тестом не подтверждаются.
